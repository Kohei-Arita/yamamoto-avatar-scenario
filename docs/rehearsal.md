# リハーサル手動チェックリスト

学会本番前に、実機（X-Gate + LiveAvatar）で以下を通しで確認する。

## 事前準備

- [ ] `.env` の `OPERATOR_TOKEN` が設定されている（未設定だと operator API は503）
- [ ] `SCENARIO_SPEECH_MODE=fixed` になっている（本番は必ずfixed）
- [ ] 単一インスタンスで起動している（Render: numInstances=1）
- [ ] LiveAvatarの最大セッション時間が、接続開始からVoting待ちを含む本番全体の時間に余裕を加えた長さをカバーしている（[5分で切れた際の調査記録](production-hardening.md#追記-5分で映像音声が切れる原因)）。keep-aliveで上限は延長できない
- [ ] 手元端末で `/operator` を開き、トークンで接続できる
- [ ] 会場画面で `/xgate?autostart=1&controls=0`（必要なら `&optoken=...`）が開ける
- [ ] 患者役の専用マイクを入力にし、会場全体を拾う内蔵マイクや、アバター音声を含むミキサーの出力を入力にしない
- [ ] ミキサー入力なら `LIVEAVATAR_MICROPHONE_AUTO_GAIN_CONTROL=false` を基準に音響担当者とゲインを調整し、小声の「はい」が通ることを確認する

## 全9経路の通し

Voting①（A=喫煙歴 / B=職業歴 / C=間質性肺炎の経過）× Voting②（A=手術 / B=放射線 / C=薬物療法）の9通りを、それぞれ挨拶→クロージングまで通す。

- [ ] A×A　- [ ] A×B　- [ ] A×C
- [ ] B×A　- [ ] B×B　- [ ] B×C
- [ ] C×A　- [ ] C×B　- [ ] C×C

各経路で確認すること:

- [ ] 開始時にシナリオ冒頭の挨拶が発話される
- [ ] 「特にありません」で症状確認 → 生活確認へ進む
- [ ] 「ここから検査結果を一緒に確認しましょう」の後、「PET/CTの画像を提示します」の発話で画像説明が始まる
- [ ] Voting待機中はマイクが止まり、拍手・司会の声・患者の声で進行が動かない。分岐の説明が終わると入力が再開する
- [ ] 分岐ボタン押下で該当セリフがアバターから発話される（operator画面に「送信しました」）
- [ ] クロージングで「専門チームで検討」「希望（低リスク・結婚式）を踏まえる」が語られる

## 救済操作

- [ ] 患者が沈黙した場合に「次へ（強制）」で進行できる
- [ ] 聞き取れなかった場合に「再発話」で同じセリフを再生できる
- [ ] サーバー再起動後に「ジャンプ」で中断ノードへ復帰できる
- [ ] 「リセット」で先頭へ戻せる
- [ ] 「入力を停止」で位置を維持したままマイクが止まり、再開後の患者発話だけが処理される
- [ ] 発話中の「ジャンプ」「再発話」で古いキューが残らず、選んだ説明へ切り替わる。autoで連結した説明も全体が再生される
- [ ] 同じノードへのジャンプやリセット中に、古い判定結果で進行しない。操作連打やキー長押しでも台本が飛ばない

## 台本外質問（3種）

以下は `patient_intent` のノードで確認する。`patient_any` のノードは有効な発話で次へ進む設計であり、全ノード共通の台本外判定ではない。

- [ ] 予後: 「あと何年生きられますか」→ 受け止め+「専門チームで検討」+ 現在の質問再提示
- [ ] 費用: 「治療費はいくらかかりますか」→ 同上
- [ ] 雑談: 「今日は暑いですね」など → 一文で受けて台本続行

## 音声・接続

- [ ] 読み仮名確認: 扁平上皮癌 / 間質性肺炎 / EBUS-TBNA / SUVmax / UIPパターン / 急性増悪 / 血痰 / #7リンパ節 / 右下葉 / 蜂巣肺 が正しく読まれる
- [ ] マイクを抜き差し（再接続）しても会話を継続できる
- [ ] 複数タブで開いた場合に2つ目のタブがロックされる
- [ ] 話し切り（既定 `LIVEAVATAR_ALLOW_INTERRUPT=false`）: アバターの発話中に患者が話しても発話が止まらず、最後まで話し切る（ログの`microphone.muted`→`microphone.unmuted`を確認。遅れて届く文字起こしは`ignored_while_speaking`）
- [ ] 発話終了直後に患者が話し始めても、その発話が拾われる（`microphone.unmuted`の後に文字起こしが届く）
- [ ] 同じテンポで10〜20秒話し、途中の文字起こしだけでアバターが返答しない。話し終わってから前半・後半を含む一つの回答として処理される
- [ ] 発話を意図的に30秒以上続けると、最初の発話検出から30秒で入力が閉じ、それまでに聞き取れた内容で一度だけ返答する。ログは `user.turn.finalized` の `reason: max_duration`
- [ ] 発話中と検出される雑音を、意味のある文字起こしがないまま30秒継続させると台本が進まず、操作画面が「停止中（操作係の再開待ち）」になる。「音声入力を再開」で同じ位置に復帰できる
- [ ] 無音で30秒待っただけでは上限停止しない。入力停止・ジャンプ・切断の後に古い30秒タイマーが発動しない
- [ ] エコー: 会場スピーカー音量を本番相当にして、アバターの発話が「患者の発話」として誤認識されない（ログに`echo_ignored`が出る）
- [ ] `autostart=1`で開いた際、音が出ない場合に「タップして音声を有効にする」が表示され、タップで音が出る
- [ ] セッションを強制切断（ネットワーク断など）→ 自動再接続され、**台本の進行位置が維持され、直前の説明から再生される**
- [ ] 進行SSEだけを切断すると入力が止まり、復帰時はその間のoperator操作を反映して再開する
- [ ] 本番同等の長いVoting待ちでkeep-aliveが成功し、再接続後も位置を引き継ぐ。契約の最大セッション時間に収まることも確認する
- [ ] Start直後に開始挨拶が音声で発話される（無音の場合はログの`watchdog.speak_start_retry`を確認）
- [ ] 分岐ボタン押下直後に患者が黙っていても台本が先へ進まない（ログに`utterance_ignored`が出る）
- [ ] 通常の通しでwatchdogによる再送が頻発せず、実際のスピーカーから全セリフが聞こえる（operatorの「送信しました」や「接続中」は可聴音声の保証ではない）

## 既知の制約

- 進行状態はサーバーメモリのみ。再起動でリセット（→ジャンプで復帰）
- `placeholder: true` のノードは監修前の仮テキスト。差し替えは `data/scenarios/haigan-2026.json` の編集のみでよい
