# 学会本番に向けた改善・リファクタリングの変更記録

初回記録: 2026-09-22 / 更新: 2026-09-23

数千人規模の会場で使う際の、雑音による誤進行、発話の中断、通信切断からの復旧、操作と音声判定の競合を対象に改善した。以下は今回の実装変更と検証結果の記録。日常の操作手順は [README](../README.md)、詳細設計は [architecture.md](architecture.md)、実機確認は [rehearsal.md](rehearsal.md) を参照する。

## 2026-09-23: 再点検と追加修正

コードと運用ドキュメントを再点検し、以下を修正した。台本JSONの医学的なセリフ、23ノード、9経路は変更していない。

| 問題                                                                               | 対策                                                                                                                 |
| ---------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------- |

| SSEの一部だけ受信して同じ進行番号で再接続すると、残りの説明が失われる              | 台詞ID・連番・総数を導入し、全件受信後に発話。進行番号が同じでも部分受信分を回収                                     |

SSE書き込み・認証・台詞一式の受信確認・SDK待機上限・二重起動防止を、それぞれ共通の処理へ分離した。ブラウザとサーバーの二重の非発話フィルタ、30秒の発話受付、UUIDによる発話照合など、役割のある防御は維持した。DockerはNode.js 22、lockfileに従ったインストール、非root起動へ更新した。

### 反映時の変更

- `OPERATOR_TOKEN` は起動時の必須設定。十分に長いランダム値を設定し、投影前に `/access` で認証する（12時間有効）。ショートカットは `/xgate?shortcuts=1`。
- サーバー更新後は会場画面・操作画面を再読み込みする。新しいSSE形式・世代管理と旧画面を混在させない。
- 発話開始・終了が確認できない場合は、実音と現在位置を確認して操作画面から再発話。SDKタイムアウトで切断した場合はStart。サーバー再起動ならジャンプ・リセット。
- 操作画面に表示する「発話開始通知あり」「発話終了通知あり」はブラウザが受け取ったイベントであり、会場で音が聞こえた保証ではない。

## 会場音響に関する設定

ブラウザの音声取得に、エコー除去・ノイズ抑制・モノラルを明示した。自動音量調整は `LIVEAVATAR_MICROPHONE_AUTO_GAIN_CONTROL` で切り替える。既定値の `false` はミキサーで入力レベルを調整する構成を想定している。

実際の本番配線は未確認。患者役と合図を出す進行役のマイクをアプリへ入力し、アバター音声を含む会場全体のミックスを入力へ戻さない構成で確認する。客席の声と患者の声の区別は、文字起こしフィルタやノイズ抑制だけでは保証できない。

## 整理したコードと維持した仕組み

- self-controlled以外の旧モード分岐、使われなくなった字幕抽出処理・ラッパー・イベント情報の深い再帰探索を削除した。
- 停止済みセッションのトークンを再利用し得る短時間キャッシュを削除した。同時に到着したトークン発行要求の集約は維持した。
- マイクのミュート状態と再試行を [microphone-controller.js](../public/microphone-controller.js) に集約した。
- ブラウザ・サーバー双方の非発話フィルタ、エコーガード、継続発話の結合、発話ウォッチドッグ、起動世代の管理を維持した。これらは誤進行や無音停止に対応する役割がある。
- 台本JSONと医学的なセリフは変更していない。台本駆動の標準経路と9通りの分岐を維持した。

## 追記: 字幕だけ進み、口も音声も動かない不具合の修正

本番向け改善の後、字幕だけがゆっくり進み、アバターが発話しなくなる不具合が発生した。発話コマンドの `event_id` に、内部識別用の接頭辞を含む `segment-<UUID>` を渡したことが原因だった。

実LiveAvatarへ接続し、同じ文を送って以下を比較した。実マイクの代わりにブラウザの合成入力を使用した。

| ID形式           | マイクトラック未公開                             | ミュートしたマイクトラック公開済み               |
| ---------------- | ------------------------------------------------ | ------------------------------------------------ |
| `segment-<UUID>` | 発話通知なし、受信音声は無音相当                 | 発話通知なし、受信音声は無音相当                 |
| 接頭辞なしのUUID | 発話開始・終了通知あり、音声エネルギーの増加あり | 発話開始・終了通知あり、音声エネルギーの増加あり |

字幕は発話開始通知が届かない場合のウォッチドッグでも表示されるため、字幕が出ることだけでは発話の成功を確認できなかった。初回の模擬接続テストはID形式を検証しておらず、この不具合を見逃していた。

修正では [liveavatar-self-controller.js](../public/liveavatar-self-controller.js) のID生成を `crypto.randomUUID()` に統一し、発話・中断コマンドへ接頭辞なしのUUIDを送るようにした。形式を検証する回帰テストを追加し、lintと実LiveAvatarで修正を確認した。[公式SDKのID生成](https://github.com/heygen-com/liveavatar-web-sdk/blob/master/packages/js-sdk/src/LiveAvatarSession/LiveAvatarSession.ts)も参照した。

さらに、修正後の `/xgate` を実LiveAvatarへ接続して開始挨拶を検証した。送信IDと一致する発話開始通知、最初の文の終了通知、次の文の開始通知、無音ではない受信音声を確認した。ウォッチドッグの発動は0回。ブラウザ・音声受信までの確認であり、会場スピーカーでの実音確認や全経路の通しとは別の検証である。

修正反映後は、既存のセッションをStopし、会場画面を再読み込みしてからStartする。読み込み済みのJavaScriptは、ファイルを更新しただけでは入れ替わらない。

## 追記: 5分で映像・音声が切れる原因

2026-09-22、Voting②の分岐を選んだ終盤に、映像・音声が突然切れた。報告されたセッションをLiveAvatarの [Get Session API](https://docs.liveavatar.com/api-reference/sessions/get-session) で照会し、以下を確認した。調査では新しいセッションを開始していない。

```json
{
  "duration": 300,
  "mode": "FULL",
  "is_sandbox": false,
  "end_reason": "MAX_DURATION_REACHED"
}
```

接続が300秒（5分）の上限に達し、LiveAvatar側で終了した。[公式イベント仕様](https://docs.liveavatar.com/docs/full-mode/events)でも `MAX_DURATION_REACHED` は最大接続時間への到達を示す。今回の原因はこの記録で確定している。

`nodeId: s2_closing` は台本エンジンの進行先であり、発話完了を示すものではない。終端到達時にアプリから接続を切る処理はない。operatorログの `delivered: true` も進行SSEへの配信を表し、最後まで発話したことの保証ではない。

同日確認した [公式プラン案内](https://help.heygen.com/en/articles/10035615-how-to-get-started-with-liveavatar) の最大セッション時間は、Starterが5分、Essentialが20分、Businessが60分。今回のAPI照会で契約プラン名までは確認していないため、契約はLiveAvatar管理画面で確認する。

本番は接続開始からVoting待ち・患者の返答を含む全体の時間に余裕を加え、その時間をカバーする契約で通す。keep-aliveは無操作切断への対策で、最大接続時間を延長する機能ではない。`autostart=1` の自動再接続は進行を引き継げるが、映像・音声の中断をなくすものではない。

開始時の上限は `/api/liveavatar/start-session` の応答にある `raw.max_session_duration` で確認できる（[公式Start Session API](https://docs.liveavatar.com/api-reference/sessions/start-session)）。終了理由の通知が届いた場合、会場画面のブラウザコンソールに `LiveAvatar disconnected: MAX_DURATION_REACHED` が出る。通知が取りこぼされた場合は、今回と同様に終了済みセッションをAPIで照会する。

## 追記: 話の途中での確定を抑え、発話受付を30秒で区切る

以前の確定処理は、文字起こしの更新が1.2秒止まった時点でLiveKitの `isSpeaking` だけを確認していた。発話中フラグが一瞬外れると、本人は話の途中でも即座にミュートして応答へ進み得た。実コードの模擬検証で、200msだけfalseにした際にも確定することを確認した。実セッションの記録にも、最初の文で応答へ進んだ後の文字起こしがLiveAvatar側に残っていた。ただし、その瞬間の発話フラグは記録されておらず、実機での直接原因までは確定していない。

改善では [user-turn-detector.js](../public/user-turn-detector.js) に受付の時間管理を分離し、LiveAvatarの発話開始・終了通知とLiveKitの発話状態を併用した。両方が終了状態となり、文字起こしの更新も止まった状態が既定1.2秒続いてから返答する。句点付きの途中結果や短い検出の途切れだけで確定しない。

ユーザーの指定に従い、1回の受付上限を最初の発話検出から30秒とした。検出通知がない場合は最初の有効な文字起こしから数える。追加の断片や開始通知で期限を延長せず、期限後の文字起こしは今回の回答へ取り込まない。

- 聞き取れた内容がある: その内容で一度だけ返答する。応答が終わるまで後続入力を閉じる。
- 有効な文字起こしがない: 台本を進めず入力を停止し、操作係を待つ。追加した `POST /api/dialogue/input-timeout` は登録済みセッション・進行番号を検証し、停止状態をサーバー・操作画面と同期する。「音声入力を再開」で同じ位置から復帰する。
- 無音待機: 発話を検出するまでは30秒タイマーを開始しない。操作・切断・停止時はタイマーを破棄し、古い受付が新しい進行を止めないようにした。

`user.turn.started` / `user.turn.finalized` に開始源・確定理由・経過時間・両方の発話状態を記録する。聞き取りなしの停止は `input_timeout` として操作画面のログにも残す。受付時間は30秒固定とし、新しい環境変数は増やしていない。既存の `LIVEAVATAR_TRANSCRIPT_DEBOUNCE_MS` と `LIVEAVATAR_TRANSCRIPT_CONTINUATION_MS` をREADMEと `.env.example` に明記した。

自動テストでは、発話通知とLiveKitの不一致、200msの検出途切れ、終了後の遅い文字起こし、連続断片・開始通知による期限延長の防止、期限後の入力拒否、雑音のみの停止、操作係の再開、古い期限通知の拒否を確認した。**126件成功、失敗0件**。会場の実マイク・音響での確認は [リハーサル手順](rehearsal.md) に追記した。
